OK so first of all, you only applied this change to the "By Found In" shopping list sorting option, but I think it should also apply to the "By Card" option, and maybe we might be able to carry over some of this logic into the "Visible Cards" section as well. Secondly, what you implemented is a good start, however there is some constraints we need to change. First of all, what I had originally envisioned was making it so that the cards in the shopping list can be variable width, in order to support 2 or 3 or maybe even more columns of items. However the way you did it still enforces all cards to be equal width and so when there are many different cards, e.g. Arc, Commericial, Residential, Nature, etc.. all containing items, and the one section has many more than the rest, then it splits the items into 3 columns of that section, however since all the cards are equal width, the only way to fit all of that information is for the cards to then extend vertically, and what happened was a very weird layout where the text inside each item bubble was laid out vertically letter over letter, and extended super far downwards. 

I think this means we need to put in a couple of constraints:

- First of all, we need to redesign the item subtitles. When sorting by "Card", the subtitle should be "Found in" with the location and the location icon, not the item type. The item type users can see by using the tooltips. Vice versa, when the shopping list is sorted by "Found In", the subtitle should be the card that the item is needed for. However, please make it so that for items that are needed for projects the name of the stage is excluded and only the (#/#) is included. In other words, the subtitle for an item needed for the High-Gain Antenna first stage should be "High-Gain Antenna (1/3)" instead of "High-Gain Antenna Sturdy Base (1/3)".
- Second, we need to have a line constraint for each item bubble. The title should be maxium 2 lines. The subtitle should also be maximum 2 lines. And the sub-sub-title, "Can also be found in..." (whenever that is applicable) should also be maximum 2 lines. So in total, the item pills should have a maximum of 6 lines of text to the right of the icon.
- Thirdly, we need to make sure that the widths of the cards can be variable and change dynamically based on the situation. If one card has a bunch more items than the other two that are also being tracked at that moment, then the one with a bunch more items should become wider. The goal is to think of all the items in the shopping list as a grid, regardless of which card they belong to. Our task would then be to design a shopping list that displays all items with the smallest possible grid footprint that still allows for a clear seperation of cards. 
- To achieve this, we may need to remove the logic you just implemented and maybe even rewrite the shopping list UI code from scratch. It should dynamically fill up the space as efficiently as possible while adhereing to our constraints of maxium 6 lines per item pill (2 for title, 2 for subtitle, and 2 for sub-sub-title) and also being seperated by cards.
